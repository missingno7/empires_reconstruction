# Naturally linked runtime DATA

The original runtime DATA tail begins with the unique 91-byte IOERROR match.
Following TLINK's extraction order and each OMF segment's word alignment yields
EXIT, STKLEN, ATEXIT, FMALLOC, FBRK, CTYPE, FILES2, FMODE and RAND. All ten
contributions match their pinned CC.LIB source and the actual full-link output:
420 source bytes and two alignment bytes from load 13186 through 1332B.

`python tools/verify_runtime_data_tail.py` checks module order, OMF alignment,
lengths, generated bytes, actual linked positions and original bytes. The
[receipt](runtime-data-tail.json) is separate from whole-EXE success: the rest
of DATA still differs and the aggregate DGROUP scaffold remains.

EXIT has three offset16 references to its own TEXT segment. Its `_exit` public
is at module offset one; these references require the segment base, not that
public. The fixed verifier now supports explicit complete-library-segment
bindings, rejecting partial ownership and ambiguous public/segment requests.
TLINK itself resolves the original segment references without this verifier.

Canonical ownership removes 165 raw bytes: 163 become pinned library DATA and
two become declared alignment. No new runtime C was introduced. RAW_012C03
shrinks from 2,039 to 1,923 bytes. The former 55-byte final raw extent becomes
six startup segment bytes (_EMUSEG and _CRTSEG), still retained as RAW until a
proper pinned startup-object ownership path is introduced. Total raw EXE bytes
are 4,135 across 12 owners.

The library tail was already correctly positioned by the baseline TLINK run;
this establishes its ownership and boundary, not a newly corrected final link.
It constrains the end of reconstructed game DATA. The shared-compilation
experiment shifts it two bytes earlier because its old aggregate scaffold
still includes separate-object sizing assumptions. Ordered source DATA must
replace that assumption without compensating arbitrary padding.
